# 共通の約束

どのパターンでも守ること。

## 決まりの置き場
- やり取りの決まりは、この plugin にだけ置く。使う側の CLAUDE.md、メモリ、作業の記録に写さない。使う側の CLAUDE.md に書くのは、次の二文だけ: 「応答の形は、やり取りの plugin に準じる。plugin が読み込まれていなければ、作業を進める前にそのことを言って止まる」
- 決まりを変えたい、足したいと分かったことは、skill `propose-change` で plugin のリポジトリ (sug1t0m0/cc-mp-test) に出す。流れは、変える所と理由をまとめる → ユーザーが出すと決めたら issue を立てる → 頼まれたら PR を出す → 使う側で打つ更新コマンドを案内する。この流れを、ユーザーにも伝える
- 新しく言われた決まりも、その場で守りつつ、同じ流れで plugin に出す。メモリに書いて済ませない

## ヘッダー
- すべての返事と、artifact の頭に、ヘッダーを書く
- 一行目は identity。hook が流した一行をそのまま書く
- 二行目以降は、パターンの決まり (dialogue.md) が定める

## 食い違い
- CLAUDE.md が二つ以上読み込まれ、中身が食い違うときは、作業を進める前にそのことを言う
- この plugin の決まりと、使う側の CLAUDE.md が食い違うときも同じ。どちらに従うかをユーザーに決めてもらい、決まりを直す案を propose-change で出す
