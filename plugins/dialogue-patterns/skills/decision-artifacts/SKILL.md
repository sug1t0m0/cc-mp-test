# 設問の二つの artifact

設問を出すセッションでは、二つの artifact を作り、セッションの間は同じ URL のまま更新する。
- 解説: 今の設問を、CLI の返事より詳しく噛み砕いたもの。図を使い、読む負担を CLI の返事より軽くする
- 進捗: セッション全体で、どんな設問を見込み、何が決まり、何が決まっていないか

## 作り方と更新
- 最初の設問を出すときに、二つとも作る
- 元の HTML は、ほかのセッションと混ざらない一時の場所に置く。リポジトリの中には置かない
- 二回目からは、最初に publish したときの URL を渡して publish し直す。ファイルのパスに頼らない
- 更新は CLI の返事と同じターンで行う。返事と中身を食い違わせない
- スマートフォンの幅で読めるように組む
- 文字は小さめにする。基準 (html) を 13px、本文を 12px にし、見出しと表はそれに比例させる
- 返事に収まらない表や図は、解説に描く
- 返事の終わりに一行で、更新した artifact とその URL を書く

## 解説に書くこと
- 設問の番号と名前。子の設問なら親の設問、末尾に足した設問なら、どの設問の話から出たか
- 何の話か、何を決めるか、なぜ今それを決めるか (設問の出し方の決まりのとおり)
- 背景と前提 (知らないと候補を比べられないこと)
- 図 (構造、流れ、前と後の違い)
- 候補ごとに、初学者向けの説明と before / after
- 推奨と、その理由
- 話す設問が変わったら、今の設問の解説に書き換える

## 進捗に書くこと
- 頭に、見込みの設問の数、決まった数、今話している設問
- 設問がすべて決まったら、頭に「このセッションの結果」を足す: 決まったこと (変えたものと要点)、やること (誰が、何を)、残っている問い。中身の無い欄は書かない
- 設問の表: 番号、何を決めるか、状態、答え
- 子の設問は親の下に字下げして並べる
- 末尾に足した設問には、どの設問の話から出たかを書く
- 状態は五つ: まだ、話し中、決まった、片付いた (ほかの設問の答えで決まった)、止めた
- 番号は CLI の返事と同じものを使う
- 見込みは変わってよい。設問を足したら表に足す。表から消さない
